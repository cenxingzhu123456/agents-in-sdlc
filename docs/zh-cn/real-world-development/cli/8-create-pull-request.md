筛选功能实现、指令更新、技能更新、质量保证（QA）配置和测试都已保存在同一分支上。现在要统一审查这些内容并创建拉取请求。之前你手动合并了星级评分 PR；这次将使用 **Agent Merge** 管理合并流程。

> [!NOTE]
> 通常会将功能、指令更新、技能更新和 QA 智能体拆分到几个独立的 PR 中。为简化研讨会流程，筛选功能和质量工作都保留在同一对话和分支中，并通过这个 PR 一并提交。

本课将：

- 了解 Agent Merge 的作用，以及它如何自动管理合并生命周期。
- 检查完整的功能更改和验证证据。
- 创建筛选功能 PR。
- 审查后启用 Agent Merge，并确认 PR 已合并。

## 场景

在筛选功能的整个开发流程中，你使用 Copilot 规划、实现并验证了功能。现在 Tailspin Toys 希望自动完成剩余的 PR 工作，同时由开发人员掌控合并授权。

## 认识 Agent Merge

**Agent Merge** 可自动完成合并拉取请求所需的剩余工作。启用后，Copilot 会处理阻碍 PR 合并的问题——修复失败的持续集成（CI）检查、回复审查意见，并在需要时变基——然后在存储库允许的情况下启用 GitHub 自动合并。

之前都是由你选择 **Merge pull request**。Agent Merge 可以代为处理这一步。启用前，请先审查工作并确认已准备就绪。

## 使用 Agent Merge 管理 PR

代码都已完成，现在统一审查、创建 PR，并让 Agent Merge 管理后续流程。

1. 返回 Codespace。
2. 输入 `/agent` 打开智能体对话框。
3. 从选项列表中选择 **Default**，然后按 <kbd>Enter</kbd>。
4. 使用命令 `/pr create` 创建新的 PR。
5. 使用 `/pr agentmerge` 激活 Agent Merge。
6. Copilot 会监控 PR 的持续集成流程。所有检查成功后，它将合并 PR。
7. 确认看到 Copilot 显示类似“PR #14 was squash-merged successfully.”的消息。

> [!IMPORTANT]
> Agent Merge 不会绕过必需的批准、分支保护、合并队列、存储库设置或权限不足等限制。如果合并受阻，请阅读报告的原因；在存储库允许的情况下，完成审查后手动合并。
