最初に小さな機能をプロジェクトに追加しました。しかし、より大きな変更には、より堅牢なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業し、適切なものを適切な方法で構築できるように設計されています。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。issue を使って新機能を作成し、コードが正しく、機能が期待どおりに動作することを確かめたうえで、プロジェクトへのマージを成功させます。

> [!NOTE]
> 機能のワークフローでは、同じセッションを使い続けます。通常は作業するファイルの種類ごとに異なるセッションや PR を使いますが、ここでは主な概念に集中できるように手順を簡略化しています。

このレッスンでは、次のことを行います。

- GitHub issue からエージェントの新しいセッションを始めます。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動で検証します。

この機能の作業を続けるなかで、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者はカテゴリや販売元でゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細もあります。Plan モードで決定事項を整理してから、Autopilot に範囲を限定した実装を許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、さらに重要になります。多くの開発者は、次のような流れで作業しています。

1. 必要な作業の詳細を記載した issue を開きます。
2. 構築する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合は上記の流れを調整したものになります。

この標準的な手順を踏むことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューのプロセスを通るようにできます。

## セッションモード

**セッションモード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプト入力欄の下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、続行前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントが完全に自律的に作業し、入力を待たずにコードを書き、テストを実行して反復します。

Plan モードから始めて計画を確認し、その後 Autopilot で実装します。

## issue からセッションを開始する

開始する前に、星評価の PR がマージ済みであり、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** の下から Tailspin Toys リポジトリフォルダーを選択し、リポジトリ上部のナビゲーションで **Issues** を選択します。既存の **Allow users to filter games by category and publisher** issue を開きます。テンプレートに用意された issue なので、新たに作成する必要はありません。
2. **New session** を選択し、更新済みの `main` を基にした **new working tree** を選択します。

    ![GitHub Copilot app の issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モードセレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` の実行を依頼します。ターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH またはバージョン管理ツールの設定を確認し、アプリを完全に終了してから再度開きます。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## 絞り込み機能を計画する

計画を立てると、Copilot がコードを書く前に実装方針を確認できます。issue から開始しているため、Copilot はすでに機能の依頼をコンテキストに含んでいます。次を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、計画を issue の受け入れ基準と照らし合わせます。カテゴリと販売元による絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが計画に含まれることを確認します。複数カテゴリをどのように組み合わせるか、一致するゲームがない場合にどうするかなど、不明確な動作について話し合います。

計画には、プロジェクトで既存のツールを使った lint、ユニットテスト、E2E テスト、型チェックを含めます。絞り込みの実装とテストに範囲を絞り、品質ワークフローを終えてから PR を作成します。計画の修正を承認前に依頼し、後で検証するために issue の URL と合意した明確化事項を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan**、または使用中のバージョンに表示される同等のオプションを選択します。承認しただけでモードが切り替わったと思い込まず、現在のモードを確認してください。モード表示が **Autopilot** であることを確認します。

Copilot が実装を開始します。確定した計画に沿って作業を進め、コードを生成してテストを実行しながら反復します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係の不足やポート競合が報告された場合は、チェック完了とみなす前にセットアップの問題を解決します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、他のコードと同様にマージ前にレビューします。コードをレビューしてサイトを実行し、すべて問題ないことを確認しましょう。

1. **Changes** を開き、絞り込み機能の実装とテストを確認します。
2. 複数カテゴリと販売元の組み合わせも含め、結果を issue と承認済みの明確化事項に照らし合わせます。変更が既存のリポジトリの指示に従っていることも確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、影響を受けるチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカルサーバーを再利用できるため、テスト対象が前のレッスンではなく、この worktree のサーバーであることを確認してください。

## 新機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを送って、アプリを起動しブラウザーキャンバスでページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリを選択し、結果が一致することを確認します。フィルターを解除して販売元を選び、結果がその販売元に一致することを確認します。
4. カテゴリと販売元のフィルターを組み合わせ、issue と承認した計画に照らし合わせます。複数カテゴリがサポートされている場合は、合意した組み合わせの動作を確認します。
5. 一致するゲームがない組み合わせを試し、空の状態を確認します。フィルターをクリアまたはリセットして、一覧全体が戻ることを確認します。
6. 確認が終わったら、次のプロンプトでこのセッションが起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンのためにセッションを保持する

絞り込み機能の PR は、まだ作成またはマージしないでください。レッスン 4 から 8 まで、同じセッション、worktree、ブランチを使います。次はカスタム指示を絞り込みコードに適用し、スキルと QA の改善を追加してから、レッスン 8 で変更をまとめた PR を作成してマージします。開発サーバーを停止したらセッションをそのままにしておき、次のレッスンで同じセッションに戻ります。

- **Plan** モードで要件を定義しました。
- **Autopilot** モードで新機能を実装しました。
