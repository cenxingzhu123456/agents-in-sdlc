絞り込み機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストが、1 つのブランチに保存されています。すべてをまとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを簡潔にするため、絞り込みと品質のワークフローを 1 つのセッションとブランチにまとめ、この PR にすべての作業を含めました。

このレッスンでは、次のことを行います。

- Agent Merge とは何か、マージのライフサイクルを自動化する方法を学びます。
- 機能全体の PR と検証の証拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされることを確認します。

## シナリオ

絞り込み機能のワークフローを通じて、Copilot で機能の計画、実装、検証を行いました。Tailspin Toys では、マージの許可は開発者の管理下に置いたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするための残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要な場合のリベースなど、マージを妨げている問題に対処します。GitHub が許可すると、プルリクエストがマージされます。Agent Merge はバックグラウンドで実行され、アプリの再起動後も作業を継続し、プルリクエストがマージされると自動的に停止します。

ここまでは自分で **Merge pull request** を選択しました。Agent Merge にその役割を任せることもできますが、コードの編集とマージには明示的な許可が必要です。マージ権限を与える前に、許可される操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR の処理を任せましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択して処理を開始します。ドロップダウンでオプションを選択するだけでは開始されません。

Agent Merge の処理が始まります。次のことを行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連 issue に言及します。
- ターゲットブランチに対してリベースし、マージ競合に対処します。
- CI プロセスを監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot code review からのフィードバックがないか PR を監視し、コメントを解決する変更を加えます。
- すべてが成功したら、必要に応じて PR を自動的にマージします。

すべてのチェックが成功した後に Agent Merge が PR をマージするように設定しましょう。

5. マージを許可する前に、PR の差分と検証の証拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. エージェントに明示的にマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告されたブロッカーに対処します。続行する前に PR の状態が **Merged** になったことを確認します。マージを許可したことやエージェントが動作中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や不足している権限を回避しません。続行する前にブロッカーを解消してください。
