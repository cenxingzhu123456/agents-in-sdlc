GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では自分のマシンで作業がリアルタイムに進むため、ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または拒否し、エディターを離れずに追加のプロンプトを送って作業を調整・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示を追加し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を始めずに、既存のセッションを案内して作業を広げます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が順に表示されます。ファイル編集は差分と **保持** / **元に戻す**の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルを編集すると、差分がインラインに表示されます。
   - 変更を承認するには **保持**を選択します。
   - 変更を取り消して、エージェントに再度作業させるには **元に戻す**を選択します。
4. チャット上部の**変更されたファイル**を開き、このセッション中にエージェントが変更したファイル一式を確認することもできます。

> [!NOTE]
> ツールの使用許可 (例: ターミナルコマンドの実行) を求められると、エージェントは一時停止して **許可**を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。会話を続けることで、エージェントは変更したコンポーネント、使用したスタイル、設定したローカルストレージのパターンなど、前の作業のコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストの場合と同様に、新しい変更を確認します。それぞれの差分で **保持**または**元に戻す**を選択します。
4. エージェントが意図しない方向に進んだ場合 (例: 好みでない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の横にある **停止**を選択してから、意図を明確にするプロンプトを送ります。

> [!TIP]
> 進行中のセッションを案内すると、最初からやり直すより短時間で調整できます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」と修正を依頼したり、「トグルを 3 つにせず、ライトモードを既存の設定パネルに追加する」と方向を変えたり、「両方の切り替えにキーボードショートカットも追加する」と範囲を広げたりできます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **ソース管理**ビューを開きます。
2. 変更されたファイルの一覧をすべて確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、ソース管理パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、セッション中の作業を監視して案内しました。ファイル編集を確認し、変更を承認または拒否し、コンテキストを維持したまま追加プロンプトを送信して作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または拒否しました。
- 追加プロンプトで進行中のセッションを案内しました。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
